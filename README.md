# 知序 · React 个人文献阅读器

> [PRD](https://github.com/lemon150637/personal-literature-reader) 的快速原型验证：React 18 重写 + 知识库问答助手——两天内验证"个人文献库 + 可溯源问答"的核心闭环。

**English: A rapid React prototype validating the PRD's core loop — personal library + traceable Q&A.**

![type](https://img.shields.io/badge/type-React%20%2B%20Vite-61dafb) ![tests](https://img.shields.io/badge/tests-6%20core%20cases-success)

## 为什么做

[个人文献阅读器 PRD](https://github.com/lemon150637/personal-literature-reader) 定义了"收集 → 阅读 → 摘录 → 思考 → 导出"的完整链路。但在改造 Koodo Reader 之前，需要先回答一个问题：**"文献库 + 问答"的体验，用户真的需要吗？**

于是用 React 从零快速搭了这个原型：不追求 PDF 解析的完整性（用正文粘贴代替），只验证核心价值假设。

## 原型验证的关键设计

- **默认无密钥可玩**：内置本地检索演示（中文分词匹配），无网络无密钥也能体验闭环；
- **真实模型可选**：配置 `.env` 后切换，密钥只在 Node 服务读取，浏览器不接触；
- **隐私边界明确**：只发送问题 + 最多 8 条片段（每条 1800 字上限），不上传整个文献库；AI 内容单独标注，不并入原文笔记；
- **引用可校验**：回答必须指向传入的 S1–S8 片段，编号不匹配直接报错；
- **6 项核心测试**：`npm test` 覆盖检索、导出逻辑。

## 如实标注的边界

PDF/Word 导入是模拟流程；内置资料是虚构示例；无向量数据库与 OCR。原型只验证交互闭环，完整能力见 PRD 路线图。

以下为工程与使用细节：

## 使用

React 18 + Vite 6 + Node.js 本地 API 服务。由原静态 demo 迁移，保留绿色研究工作台布局，新增知识库问答助手及功能设置。

安装 Node.js 22.12+ 或当前机器已有 Node.js 24。

- 桌面交付版本已包含依赖与生产构建，双击“启动阅读器.cmd”。
- 浏览器访问 http://127.0.0.1:3100 。保持服务窗口运行。
- 修改源码：`npm run dev`；构建：`npm run build`；启动生产版：`npm start`；测试：`npm test`。
- 新机器安装：`npm ci`，然后 `npm run build`、`npm start`。
- 本版本不支持双击 index.html 直接运行，入口已改为启动脚本。

## 知识库助手

侧栏“知识库助手”提供问答入口；“功能设置”中可开关助手、切换模式、设置参考片段上限、选择是否包含个人思考。助手页面可选检索主题。

### 本地检索演示（默认）

无需密钥或联网，按中文双字词/英文词匹配正文、摘录与可选的个人思考；返回原文片段及来源。它不是大模型回答，也不是向量语义检索。低相关度或没有命中时提示材料不足。

### 真实模型

1. 将 `.env.example` 复制为 `.env`。
2. 填写 `AI_BASE_URL`（兼容 Chat Completions 的 API 根地址）、`AI_MODEL` 和 `AI_API_KEY`。
3. 重启服务，进入功能设置选择“真实模型”。
4. 助手页面会显示配置的服务地址。确认允许发送当前问题与检索片段后，才能发送。

密钥只在 Node 服务读取，不能写入 VITE_ 开头的变量；`.env` 已加入 Git 忽略。
服务仅监听本机 127.0.0.1。浏览器先检索，服务端仅发送问题和最多 8 条、每条最多 1800 字的片段；不会上传整个文献库。
默认 API 根地址只是配置示例，未内置密钥或模型名称。真实模型需按所选服务商填写。
兼容性范围：`POST /chat/completions`、messages、非流式 choices[0].message.content。要求模型输出 JSON 格式 answer/citationIds；不支持的返回格式会显示错误。
回答引用必须指向此次传入的 S1–S8。此校验仅保证编号存在，不保证模型陈述正确。AI 内容单独标注，不自动并入原文或个人笔记。
会话为单轮检索，历史对话仅在当前页面展示，不发送给模型；刷新会清空会话。返回文献查看出处后再打开助手，当前页面会话仍保留。

## 数据及旧版迁移

与旧 demo 使用相同 localStorage 键 zhixu-demo-v1，因此在同一浏览器、同一 http://127.0.0.1:3100 地址下自动读取旧资料。
原先以 file:// 打开的数据不属于此 HTTP 地址，无法直接自动迁移。本次不清理旧版文件或浏览器数据。
文献、摘录、思考与设置存于浏览器；清理站点数据会删除它们。项目文件夹本身不包含用户的浏览器资料。
主题 JSON 导出包含选定摘录、个人思考及其关联文献；不等于完整库备份，也不包含全部未摘录正文。

## 已支持

- 文献搜索、格式/主题筛选、排序、阅读状态。
- 正文粘贴导入（含可选作者、来源 URL），导入后可直接检索问答。
- 段落内文字摘录、个人思考、原文定位、复制出处。
- 主题 JSON 导出与复制，原文和思考分开标记。
- 本地知识库检索演示；真实模型 API 接入；来源回溯。

## 边界

PDF/Word 文件导入与 URL 导入仍为模拟流程，没有解析文件或抓取网页。真实内容请使用正文粘贴。
内置资料和作者是虚构示例，不能作为真实引文或法律依据。
知识库按段落检索，无 OCR、向量数据库、自动法律效力核验、多用户权限、云同步。
真实服务需要用户配置密钥；本次交付不包含外部模型的联网实测。

旧静态版保存在桌面项目的 legacy-demo 目录。
